# Использование в разных проектах

Глобальный навык доступен из разных проектов Codex на той же машине. Он не привязан к языку программирования, фреймворку или одному репозиторию. Откройте правильную папку проекта, напишите «подключи Claude как помощника» и опишите задачу. Указывать `$codex-claude-council` необязательно; явный вызов по-прежнему доступен.

Codex подхватывает изменения навыков автоматически. Если обновление не появилось, перезапустите приложение. Подробнее в [справке Codex](https://learn.chatgpt.com/docs/build-skills#how-codex-uses-skills).

Перед использованием установите навык по [инструкции](../README.md#установка-в-codex) и убедитесь, что вход в Claude Code работает.

## Что делает пользователь, а что делает Codex

Пользователь описывает желаемый результат, ограничения и известные симптомы. Codex читает материалы, составляет проверяемый план, выбирает соразмерные проверки и конечный бюджет, сохраняет состояние и вызывает контроллер. Пользователю не нужно знать названия внутренних фаз или вручную создавать JSON.

Уточнение потребуется, если существенный факт нельзя установить из доступных материалов. Обычные обратимые технические решения не требуют остановки работы. До ответа на существенный вопрос продолжается только независимая часть задачи.

## Разработка новой функции

```text
$codex-claude-council Добавь сохранение черновика формы между перезагрузками.
Сначала изучите с Claude текущие переходы состояния и требования к данным.
Разложи работу на проверяемые блоки и шаги. Не меняй существующие правила
отправки формы. После каждого крупного блока проведи независимое ревью
Claude, а в конце проверь весь сценарий восстановления и отправки черновика.
Не добавляй сервер или новую зависимость без установленной необходимости.
```

У этого условного запроса макроуровень может включать хранение, восстановление и интеграцию с отправкой. Микроуровень задаётся после чтения текущего проекта: например, изменение поля, сохранение, перезагрузка, восстановление и корректное очищение после успешной отправки. Это пример структуры, а не готовая архитектура для любого проекта.

## Сложная ошибка

```text
$codex-claude-council Найди причину, почему событие иногда обрабатывается
дважды. Сначала собери фактическую последовательность вызовов и воспроизведи
случай. Пусть Claude независимо изучит первичные данные и предложит
различающие проверки. Не принимайте предположение о повторном запросе
за причину, пока оно не подтверждено. После исправления проверьте связанные
обработчики и передайте завершённый блок на независимое ревью.
```

Claude можно подключить для разбора нового сложного вопроса в середине работы, даже если предыдущий этап уже проверен. Все обсуждения используют общий бюджет задачи.

## Аналитика или решение без изменения кода

```text
$codex-claude-council Сравните два предложенных процесса обработки обращений
по приложенным материалам. Сначала независимо проверьте исходные факты,
затем сопоставьте варианты по трудозатратам, риску ошибок и сохранению данных.
Не придумывайте отсутствующие цифры и не подменяйте неизвестное оценкой.
Проверьте, следует ли каждый существенный вывод из данных, какая непроверенная
предпосылка может изменить выбор и как выбранный процесс может дать сбой.
Сформулируйте вывод только в пределах подтверждённых данных; отдельно
покажите, каких фактов не хватает для окончательного решения.
```

Для анализа Codex сохраняет источники и основания выводов. Если существенный факт недоступен, он указывает, какой вывод пока нельзя подтвердить. Согласие моделей не заменяет исходные данные.

Например, в условном отчёте число обращений снизилось после изменения процесса. Само совпадение по времени ещё не доказывает, что причиной стало изменение: могло уменьшиться число пользователей. Проверка должна различить эти объяснения. Если нужных данных нет, причинный вывод остаётся неподтверждённым. Для этого не нужно создавать отдельный этап или повторять все вопросы при каждой простой правке.

## Постоянное правило в одном проекте

Если вы хотите применять навык ко всем существенным задачам определённого проекта, можно **по вашему запросу** добавить в его `AGENTS.md` небольшой раздел:

```markdown
Для существенной разработки, сложных ошибок и аналитических решений
используй глобальный skill codex-claude-council. Текущий Codex ведёт работу;
Claude независимо исследует сложные вопросы и проверяет каждый завершённый
макроблок. Сохраняй исходные требования, доказательства и конечный бюджет.
Не запускай дополнительный Codex и не создавай рекурсивное делегирование.
```

Это правило не нужно копировать целиком из протокола. Установка глобального навыка сама по себе не изменяет `AGENTS.md` ваших проектов.

## Технический пример для проверки установки

Из корня клонированного репозитория:

```bash
COUNCIL="$(pwd)/scripts/council.py"
DEMO_ROOT="$(mktemp -d "${TMPDIR:-/tmp}/council-demo.XXXXXX")"
mkdir "$DEMO_ROOT/project"
cp examples/demo/ratio.py examples/demo/test_ratio.py "$DEMO_ROOT/project/"
python3 "$COUNCIL" init --project "$DEMO_ROOT/project" --state-root "$DEMO_ROOT/state" --intake examples/intake.json
```

Последняя команда выводит абсолютный путь задачи. Для дальнейших команд сохраните **этот фактический путь** в переменную `TASK`. Не подставляйте выдуманный идентификатор. Проверка самой функции:

```bash
python3 "$COUNCIL" check --task "$TASK" --id unit --timeout 30 -- python3 -B -m unittest -v
```

Реальное ревью, в отличие от автономных тестов контроллера, обращается к Claude и расходует соответствующий лимит:

```bash
python3 "$COUNCIL" call --task "$TASK" --phase REVIEW --stage implementation --goal "Независимо проверь исходное требование, код и фактические результаты unit."
python3 "$COUNCIL" checkpoint --task "$TASK" --stage implementation
python3 "$COUNCIL" finalize --task "$TASK"
python3 "$COUNCIL" status --task "$TASK"
```

Это временная демонстрация. Для настоящей работы используется постоянный каталог `$HOME/.local/state/codex-claude-council`, если пользователь или проект явно не задали другой путь вне проекта. Существующая задача сохраняет прежний фактический путь. Если Claude обнаружит замечание, следуйте процедуре исправления из [протокола](../references/protocol.md), а не ожидайте автоматического PASSED от примера.

## Границы переносимости

Состояние привязано к абсолютному пути проекта, а сессия Claude хранится его установленным CLI. Перемещение папки или другой компьютер не являются обычным продолжением без проверки путей и доступности сессии. Автоматической синхронизации нет.

В Git учитывается корень рабочего дерева. Если чат открыт в подпапке, Codex должен определить корень, а не передавать подпапку как отдельный репозиторий. Подмодули и ссылки на каталоги не пропускаются молча: текущий контроллер останавливается и требует отдельного определения проверки. Для проекта без Git полноту входов определяют scope, файлы требований и маршрутов.
