# Прерывание и решения пользователя

## Обычное продолжение

Попросите Codex продолжить прежнюю задачу в том же проекте. По умолчанию и создание, и поиск используют `$HOME/.local/state/codex-claude-council`. Он должен найти сохранённую запись, проверить состояние процесса и актуальность файлов, а затем продолжить конкретную сессию. Если пользователь или проект ранее задали другой каталог, используется тот фактический путь, который Codex сохраняет в передаче контекста. Пустой результат поиска требует найти прежний путь по доступным материалам или уточнить его у пользователя. Создавать новую задачу вместо ненайденной записи или для обнуления лимита нельзя.

Для ручной диагностики сначала задайте фактические пути `COUNCIL`, `PROJECT` и `STATE_ROOT`, затем:

```bash
python3 "$COUNCIL" list --project "$PROJECT" --state-root "$STATE_ROOT"
```

Сохраните абсолютный путь выбранной задачи из результата `list` в переменную `TASK`, затем проверьте её состояние:

```bash
python3 "$COUNCIL" status --task "$TASK"
```

Если процесс ещё работает, просмотр статуса не запускает новую модель. Чтобы остановить именно его:

```bash
python3 "$COUNCIL" stop --task "$TASK"
```

После аварийного исчезновения управляющего процесса:

```bash
python3 "$COUNCIL" recover --task "$TASK"
python3 "$COUNCIL" status --task "$TASK"
```

Блокировка может сохраняться, пока наблюдатель завершает дочернюю группу и записывает результат. Не удаляйте её и не запускайте параллельную сессию. Дождитесь завершения очистки и повторите локальную проверку состояния.

## Что сохраняется

Исходное задание, матрица требований, макро/микроплан, замечания и решения, доказательства с версией файлов, идентификаторы сессий, журнал, контрольные точки блоков и счётчики. Бюджет времени включает период прерывания.

Прерванный ответ не становится успешным из-за наличия файла stdout. Прерванная повторная проверка не использует старый успешный тест вместо нового. После изменения кода прежние доказательства требуют актуализации. Если Claude не успел создать сохранённую сессию, точное продолжение может оказаться недоступно; это сообщается как ограничение, а не скрывается созданием другой сессии.

## Когда нужен человек

1. **Цели несовместимы.** Например, требуются одновременно сохранение всех данных и необратимое удаление тех же записей. Codex должен назвать противоречие и варианты.
2. **Нужно изменить исходные требования или объём.** Нельзя молча ослабить критерий, чтобы ревью прошло. Текущая матрица неизменяема через обычные команды; существенное изменение требует отдельного явного решения и сохранения связи с предыдущей работой.
3. **Остаётся существенный риск.** Только пользователь может принять его. Решение двух моделей не заменяет разрешение.
4. **Нужно опасное действие без ранее данного разрешения.** Например, необратимое удаление данных. Вызов навыка не выдаёт дополнительных прав.
5. **Исчерпан бюджет, но есть обоснованный следующий шаг.** Codex сообщает, что уже выяснено, что осталось и какую конкретную проверку предлагают выполнить. Расширение допускается только после явного решения пользователя.
6. **Нет нужного доступа или исходного факта.** Уточняется только действительно отсутствующая информация; независимая работа продолжается.

## Пример решения о дополнительном бюджете

Условное сообщение Codex:

> Осталось проверить влияние исправления на повторную обработку очереди.
> Локальная ошибка исправлена, но интеграционный сценарий ещё не подтверждён.
> Предлагаю добавить три обращения к Claude и тридцать минут для воспроизведения,
> исправления при необходимости и заключительного ревью. Альтернатива —
> сохранить задачу как BLOCKED до появления тестового окружения.

Условный ответ пользователя:

> Разрешаю для этой же задачи ещё три обращения и тридцать минут на указанную проверку.

Codex сохраняет решение и использует `extend-budget`. Текущая задача, прежние замечания и потраченный лимит остаются на месте. Дополнительный бюджет не отменяет обязательных проверок.

## Почему есть пределы

Длительность хорошего разбора определяется сложностью задачи, а не требованием ответить за два сообщения. При этом бесконечный обмен без нового факта бесполезен. Поэтому используются общий конечный бюджет, реальные точки проверки и остановка при отсутствии прогресса. Достижение предела не превращает спорный результат в успешный.
