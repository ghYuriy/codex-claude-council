# Версия 1.5.3: точные копии ответов и diff

Исправлены прежние дефекты сохранения копий и чтения diff. Новые копии побайтово совпадают с тем, что они копируют, и на них можно ссылаться; прежние искажённые копии восстанавливаются там, где это можно сделать проверяемо (см. ниже). Ошибка Git больше не выдаётся за пустой diff или за проект без Git (пределы — в разделе «Границы»).

## Что исправлено

- **Копия отклонённого ответа.** Для обратной связи и предварительных находок контроллер сохраняет копию ответа помощника (`evidence/rejected-<id>/stdout.json`). Раньше она читалась с преобразованием переводов строк. Если ответ содержал `\r\n`, копия не совпадала с хешем оригинала, и ссылка на неё отклонялась («Rejected response artifact was altered»). Теперь копия — точные байты ответа, и перед копированием ответ сверяется с записанным хешем.
- **Diff снимка.** Diff Git сохранялся после декодирования с заменой байтов, которые не являются UTF-8. Если в проекте был изменён текстовый файл в другой кодировке, сохранённый diff не совпадал с записанным хешем, и ссылка на него отклонялась («Git audit diff was altered»). Теперь diff сохраняется так, как его выдал Git: и в контексте Git (версия состояния 4 и новее), и в каталоге снимка (версии 1–3). Перед сохранением заново полученный diff сверяется с хешем, записанным в снимке, до записи чего-либо: если проект изменился между этими шагами, команда останавливается и её нужно повторить, а чужой diff не сохраняется. `init` делает эту сверку до создания каталога задачи, поэтому отказ можно просто повторить. У снимка, снятого без Git, сохраняется пустой diff, даже если репозиторий появился позже. Прежняя версия в этом случае сохраняла вывод Git на момент сохранения, и он мог не совпасть со снимком.
- **Ошибка Git.** Если Git завершался с ошибкой (например, из-за неверной настройки Git в окружении), контроллер мог принять это за пустой diff или за проект без Git, записать такой снимок и передать помощнику пустой `diff.patch`. Теперь:
  - ошибка `git diff` останавливает команду с причиной «Cannot read the Git diff» до запуска помощника. Исключение одно: `base_ref` не задан, а проверка `HEAD` сообщает, что в текущей ветке ещё нет коммита (новый репозиторий или новая ветка без коммитов); тогда сравнивать не с чем и diff пустой. Причину ошибки самой команды сравнения в этом случае контроллер не различает;
  - тот же признак ветки без коммита используется при составлении списка изменений для проверки. Раньше им считалась любая ошибка проверки `HEAD`;
  - если Git не может открыть репозиторий проекта, команда, в том числе `init`, останавливается с причиной «Cannot inspect the Git repository». Ошибкой, а не проектом без Git, такой сбой считается при любом свидетельстве репозитория: задача при `init` записала, что создана в Git (`git_worktree: true`), у задачи есть `base_ref`, в проекте есть `.git` (каталог, файл или ссылка) или в окружении задан непустой `GIT_DIR`. Переменная `GIT_WORK_TREE` и пустой `GIT_DIR` репозиторий не указывают и свидетельством не считаются.
- **Понятный отказ вместо исключения.** Изменённый сохранённый текст, который не читается как UTF-8, теперь даёт обычный отказ «Retained snapshot artifact changed», а не исключение декодирования.

## Копии, сохранённые прежними версиями

Сохранённые копии по-прежнему неизменяемы. Исключение одно: копия, сохранённая прежней версией в искажённом виде, заменяется точной, когда контроллер сохраняет её снова или проверяет ссылку на неё (в отчёте, `--exchange`, плане исправления). Поэтому восстановление не зависит от того, будет ли копия ещё раз передана помощнику. Замена происходит, только если копия в точности равна прежнему искажённому виду того же оригинала:

- для ответа — сам ответ с переводами строк `\r\n` и `\r`, приведёнными к `\n`, причём ответ сверен с записанным хешем;
- для diff текущего снимка — вывод Git, декодированный с заменой, причём заново полученный вывод сверен с хешем, записанным в снимке.

Любое другое расхождение, как и раньше, останавливает работу. Diff прошедших снимков контроллер заново не формирует: если такой diff был сохранён с заменой байтов, ссылка на него по-прежнему отклоняется. Контроллер не восстанавливает его автоматически, хотя исходные байты иногда можно получить вручную из сохранённых версий файлов и сверить с записанным хешем.

## Границы

- Без `base_ref` diff строится относительно `HEAD`. Если в текущей ветке ещё нет коммита, сравнивать не с чем, и diff пустой, как и раньше; полные файлы задачи помощник обязан прочитать в любом случае, а контроллер проверяет заявленное в отчёте покрытие. Неверный `base_ref` отклоняется ещё при `init`. В остальных случаях ошибка Git при определении репозитория или чтении diff останавливает команду.
- Если Git не может открыть проект, а ни одного свидетельства репозитория из перечисленных выше нет, проект считается проектом без Git. Для настоящего репозитория так бывает, только если у задачи нет записи о Git (она создана вне Git или прежней версией без `base_ref`) и Git находил репозиторий без `.git` в проекте и без `GIT_DIR`: например, в родительском каталоге, когда корнем рабочего дерева проект делала `GIT_WORK_TREE`. Если в такой задаче Git перестанет работать, контроллер сочтёт её проектом без Git. Задача, при создании которой Git успешно распознал репозиторий, записывает `git_worktree: true` и под эту границу не попадает; если в таком расположении Git сломан уже при `init`, задача создаётся как проект без Git.

## Совместимость

- Версия состояния не меняется (7). Задачи всех версий продолжаются без пересоздания. Новые задачи записывают в состояние признак `git_worktree`; прежние версии контроллера его не используют.
- Ответы без `\r` и diff без байтов вне UTF-8 сохранялись точно и раньше, для них ничего не меняется.
- Задача, у которой Git перестал открывать репозиторий или выдавать diff, теперь останавливается с причиной, а не продолжается с пустым diff (за пределом, описанным в разделе «Границы»). Продолжить её можно после исправления окружения Git.

Отдельно проверен реальный переход: задачу создал и продолжил код 1.5.2 (ответ помощника с `\r\n`, файл в кодировке не UTF-8), затем её продолжил 1.5.3 — та же сессия, diff восстановлен точным, ссылка на копию ответа её восстановила.
